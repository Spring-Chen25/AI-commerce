## 1. 项目定位

这是 CrossPilot 跨境电商运营平台的**统一后端基座**。它不含任何具体业务（选品 / 补货 / 预测 / 内容生成 / 智能问数 / 驾驶舱），只提供所有业务模块共用的基础设施：配置、异常、响应、日志、6 类外部连接、认证、幂等、审计、多库 ORM、迁移、健康检查。

**核心设计原则（改动前务必理解）**：

| 原则 | 含义 |
|---|---|
| 纯净基座 | 无业务示例、无 demo 路由；只留 `/health`、`/ready` 两个探针 |
| 延迟导入 | 第三方包（redis/minio/pymilvus/asyncpg/jwt/celery）**只在真正连接/调用时 import**，未安装也不影响启动 |
| 优雅降级 | 外部连接未配置或未装包时 `health()` 返回 `disabled`/`error`，只记日志、不抛异常、不阻塞启动 |
| 全异步生命周期 | 连接器 `connect/close/health` 均为 `async`，同步 SDK 用 `asyncio.to_thread` 包装防阻塞 |
| 单一职责 | 路由只管转发、service 只管业务、dao 只管数据、connectors 只管连接能力 |

## 3. 快速开始

### 3.1 安装依赖

```bash
cd ai_ecommerce
python3.11 -m venv .venv
# Windows: .venv\Scripts\activate   Linux/Mac: source .venv/bin/activate
python -m pip install -r requirements.txt
```

> 依赖按六模块合并、已在 Python 3.11 下做过解析校验无冲突。重型可选包（torch / prophet / pytorch-forecasting）默认注释，按需放开。
> 若 pip 源不可达，用官方源：`-i https://pypi.org/simple`。

### 3.2 配置

复制模板并按需修改：

```bash
cp .env.example .env
```

`.env` 已预填本地开发的真实连接（MySQL / PG / Redis / MinIO / Milvus）。关键约定：

- **连接类配置留空 = 未启用**，对应连接器 `health()` 返回 `disabled`，不阻塞启动。
- **密码中的特殊字符必须 URL 编码**：MySQL 密码 `Root@123456` → `Root%40123456`（`@` → `%40`）。
- **驱动分工（易错点）**：`DATABASE_URL` 用**同步**驱动 `postgresql+psycopg://`（ORM 用）；`POSTGRES_URL` 用**异步**驱动 `postgresql+asyncpg://`（连接器用）。两者指向同库，各司其职，正是 psycopg + asyncpg 共存的设计初衷。

### 3.3 启动

```bash
# 方式一：入口直跑（DEBUG=true 时自动 reload）
python main.py

# 方式二：uvicorn（推荐，可控性更强）
python -m uvicorn main:app --host 0.0.0.0 --port 8000 --reload
```

启动日志会看到 6 个连接器逐个初始化：`connected`（连上）/ `disabled`（未配置）/ `init failed`（未装包或网络不通，已降级）。**任何情况都不阻断启动**。

### 3.4 验证

```bash
curl http://127.0.0.1:8000/health     # 存活探针 → {"code":200,"data":{"status":"ok"}}
curl http://127.0.0.1:8000/ready      # 就绪探针 → 各连接器状态汇总
```

接口文档：浏览器打开 `http://127.0.0.1:8000/docs`（FastAPI 自动生成）。

## 4. 核心机制详解

### 4.1 应用生命周期（main.py）

`lifespan` 统一托管连接器的初始化与释放：

```python
@asynccontextmanager
async def lifespan(app):
    conn_status = await init_all()      # 并发连接所有已配置连接器
    logger.info("startup_complete ...")
    yield
    await close_all()                   # 并发释放（优雅关闭阶段）
    logger.info("shutdown_complete")
```

中间件挂载顺序（FastAPI **后注册的先执行**）：

```
请求 → access_log(request-id) → Audit → Idempotency → CORS → 路由
响应 ← access_log ← Audit ← Idempotency ← CORS ← 路由
```

`access_log` 还负责注入 `X-Request-ID`，并给 `/api/v1/*` 响应加 `X-Api-Envelope: 1` 头（表示响应体遵循统一信封）。

### 4.2 路由注册（routers/__init__.py）

新增路由只改这一处，main.py 不感知具体路由：

```python
def register_routes(app, api_prefix="/api/v1"):
    app.include_router(health.router)               # 探针挂根路径
    # from app.routers import xxx
    # app.include_router(xxx.router, prefix=api_prefix)   # 业务挂 /api/v1
```

### 4.3 统一响应（schemas/common.py）

所有成功响应走 `ok()`，结构为 `{code, message, data}`：

```python
from app.schemas.common import ok, PageData

return ok({"id": 1})                          # 单条
return ok(PageData(items=[...], total=9, page=1, page_size=10))  # 分页
```

### 4.4 全局异常（exceptions/）

业务层抛类型化异常，全局 handler 统一转结构化响应，**不向客户端暴露堆栈**。

可用异常（`exceptions/base.py`）：

| 异常 | code / HTTP | 用途 |
|---|---|---|
| `NotFoundException` | 404 | 资源不存在 |
| `ValidationException` | 422 | 参数校验失败 |
| `ConflictException` | 409 | 资源冲突 |
| `UnauthorizedException` | 401 | 未授权 |
| `ForbiddenException` | 403 | 禁止访问 |
| `InternalException` | 500 | 内部错误 |
| `ConnectionException` | 503 | 外部连接不可用 |
| `ExternalServiceException` | 502 | 外部服务调用失败 |

自定义业务错误：

```python
from app.exceptions import AppException
raise AppException(message="余额不足", code=40001, data={"need": 100})
```

`handlers.py` 注册 4 类 handler：`AppException` / `RequestValidationError`(422) / `StarletteHTTPException`(原生 404/405 纳入信封) / `Exception`(兜底 500)。

### 4.5 外部连接器（utils/connectors/）★

统一入口：

```python
from app.utils.connectors import init_all, close_all, health_all, get

health = await health_all()          # 并发探测，{name: {"status": ...}}
redis_conn = get("redis")            # 未注册抛 ConnectionException
```

**6 个连接器的取用方式**（都已连好、可直接用）：

| 名称 | 取用方法 | 返回值 |
|---|---|---|
| `mysql` | `get("mysql").get_engine()` | SQLAlchemy 同步 engine |
| `pgsql` | `get("pgsql").create_session()` | 异步 session 上下文 |
| `redis` | `get("redis").get_client()` | `redis.asyncio` 客户端 |
| `minio` | `get("minio").get_client()` / `.get_bucket()` | MinIO 客户端 / 桶名 |
| `milvus` | `get("milvus").get_client()` / `.get_alias()` | pymilvus connections / 别名 |
| `celery` | `get("celery").get_app()` | Celery app（声明任务用） |

取用前建议判断是否就绪：

```python
conn = get("redis")
if conn.is_connected:
    await conn.client.set("k", "v")
```

**新增一个连接器**的标准做法：

1. 在 `connectors/` 新建 `xxx.py`，继承 `BaseConnector`；
2. 实现 `enabled` 属性 + `connect()` / `_do_close()` / `_do_health()` 三个 async 方法；
3. 第三方包在 `connect()` 内延迟导入；同步 SDK 用 `asyncio.to_thread` 包装；
4. 文件末尾 `connector = XxxConnector()`；
5. 在 `connectors/__init__.py` 里 `registry.register(xxx.connector)` 并加入导入与 `__all__`。

**BaseConnector 契约**：`init/close/health` 均为 async，任何失败只记录不抛出；`is_connected` 反映底层客户端是否就绪；`client` 属性在未连接时抛 `ConnectionException`。

### 4.6 多库 ORM（database.py）

默认库绑定 `settings.DATABASE_URL`，**惰性创建引擎**（首次用时才建，缺驱动也能 import）：

```python
from app.database import get_session, get_db, register_database, Base

# 方式一：依赖注入（推荐，每请求一会话自动关闭）
def route(db=Depends(get_db)): ...

# 方式二：手动取会话
with get_session() as db: ...

# 注册额外库
register_database("warehouse", "mysql+pymysql://...") 
with get_session("warehouse") as db: ...
```

分库模型：继承 `BindKeyMixin` 并声明 `__bind_key__`，DAO 据 `get_session(model.__bind_key__)` 选库：

```python
from app.models.base import BindKeyMixin, Base
class WarehouseItem(BindKeyMixin, Base):
    __bind_key__ = "mysql"
    ...
```

> 建表由 Alembic 管理；`create_all()` 仅供开发/测试显式调用，启动流程不自动建表。

### 4.7 JWT 认证（utils/security.py + dependencies.py）

骨架级，未全局挂载，业务路由按需使用：

```python
from app.utils.security import create_access_token
from app.utils.dependencies import get_current_user
from fastapi import Depends

token = create_access_token(subject="user-123", extras={"role": "admin"})

@router.get("/me")
def me(user=Depends(get_current_user)):
    return ok(user)   # 缺 token / 无效 → 401
```

`JWT_SECRET_KEY` 生产环境必须用环境变量注入强随机密钥替换占位值。

### 4.8 幂等（utils/idempotency.py）

请求头带 `Idempotency-Key` 的 POST 会防重复提交：同 key 回放首次响应。存储**优先 Redis**（`idem:` 前缀 + 10 分钟 TTL），Redis 未连接时自动降级内存 dict。读写异常一律吞掉，绝不影响主流程。

### 4.9 审计（utils/audit.py）

`AuditMiddleware` 只审计写方法（POST/PUT/PATCH/DELETE），记录 `request_id / 方法 / 路径 / IP / 用户 / 状态码 / 耗时` 到结构化日志，**并落库到 `audit_log` 表**（模型 `models/audit.py`，迁移 `0001_initial.py`）。`write_to_db(event)` 用 `asyncio.to_thread` 包装同步会话避免阻塞，任何失败（未配库/表不存在/缺驱动）只记 debug 日志并吞掉，绝不影响主流程。

### 4.10 日志（utils/logging.py）

`setup_logging()` 在 main.py 启动时调用一次；控制台 + `logs/app.log` 按大小轮转（10MB × 7）。各模块 `get_logger(__name__)` 取 logger。

### 4.11 健康检查与健康判定

- `/health`：进程存活即可用。
- `/ready`：并发探测所有连接器；全非 error → `ready`，否则 `degraded`（`disabled` 不算故障）。

### 4.12 数据库迁移（Alembic）

```bash
# 修改模型后生成迁移
alembic revision --autogenerate -m "add xxx table"
# 应用迁移
alembic upgrade head
```

`migrations/env.py` 从 `settings.DATABASE_URL` 注入连接并导入全部模型；`versions/0001_initial.py` 是初始迁移（建立 `audit_log` 表）。后续业务表用 `revision --autogenerate` 生成。首次部署先 `alembic upgrade head` 建表（启动流程不自动建表）。

## 5. 如何新增一个业务模块（标准流程）

以「商品 product」为例，完整链路：

1. **模型** `app/models/product.py`：继承 `Base`，定义字段。
2. **注册模型** `app/models/__init__.py`：`from app.models import product`（autogenerate 依赖）。
3. **Schema** `app/schemas/product.py`：定义 `ProductOut` / `ProductIn`。
4. **DAO** `app/dao/product.py`：封装 CRUD，用 `get_db()` 会话。
5. **Service** `app/services/product.py`：编排业务，抛 `AppException` 子类。
6. **Router** `app/routers/product.py`：`APIRouter`，调 service，用 `ok()` 返回。
7. **注册路由** `app/routers/__init__.py`：`include_router(product.router, prefix=api_prefix)`。
8. **迁移建表**：`alembic revision --autogenerate -m "add product"` → `alembic upgrade head`。
9. **验证**：重启服务，`curl /api/v1/products`，看 `/docs`。

## 6. 关键约定与已记录的问题

| # | 事项 | 说明 |
|---|---|---|
| 1 | 驱动分工 | `DATABASE_URL`=同步 psycopg；`POSTGRES_URL`=异步 asyncpg；勿在同一 DAO 混用 |
| 2 | 密码 URL 编码 | 特殊字符（@ : # 等）必须编码，`@`→`%40` |
| 3 | 事件循环 | 连接器全 async；同步 SDK 用 `to_thread`，禁止在 lifespan 里 `run_until_complete` |
| 4 | MinIO 自动建桶 | 连接时桶不存在会自动创建（已确认保持此行为），会在真实 MinIO 产生副作用 |
| 5 | Celery 地址 | 当前假设复用 Redis：broker=db/1、backend=db/2（与缓存 db/0 隔离）——**假设值，可按实际调整** |
| 6 | 审计落库 | 已实现：写日志 + 落 `audit_log` 表；落库失败自动吞掉降级为仅日志 |
| 7 | Alembic | 已有初始迁移 `0001_initial`（audit_log 表）；业务表用 revision 生成 |
| 8 | psycopg2 | 已补 `psycopg2-binary==2.9.10`（兼容最初的 psycopg2 连接代码），与 psycopg3 共存 |
| 9 | 响应头大小写 | HTTP 头大小写不敏感，urllib 读到的是小写键（如 `x-api-envelope`） |
| 10 | Vanna2 / LLM | 独立服务独立 venv，不进主环境 |

## 7. 常见问题（FAQ）

**Q：启动报 `ModuleNotFoundError: No module named 'redis'`？**
A：这是延迟导入的正常降级路径被触发时记的日志，不是致命错误。要么装对应依赖，要么把 `.env` 里该项留空（返回 `disabled`）。

**Q：`/ready` 显示某连接器 `error`？**
A：看启动日志的 `connector[xxx] init failed` 具体原因——缺包 / 网络不通 / 认证失败。装包后重启即可。

**Q：改了 `.env` 没生效？**
A：`settings` 是模块级单例 (`get_settings()` 带 `lru_cache`)，需**重启进程**。

**Q：为什么 `import main` 在没装 psycopg 时不报错？**
A：`database.py` 用惰性引擎，连接串只注册不立即 `create_engine`，首次用库时才建引擎。这是刻意设计，保证纯净环境可 import。

**Q：如何临时用 SQLite 本地开发？**
A：把 `.env` 的 `DATABASE_URL` 改为 `sqlite:///./ai_ecommerce.db` 即可（其余连接器不受影响）。
